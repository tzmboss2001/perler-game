1. 模板体系：先把“可用拼豆积木种类”定义清楚
1.1 模板分类维度

建议至少按这 3 个维度组织模板：

类别（category）

character：人物 / 卡通人偶（Q 版、像素人）

animal：猫、狗、兔子、小恐龙

vehicle：小汽车、卡车、火车头

building：小房子、城堡塔楼、亭子

object：礼盒、宝箱、树、心形、星星

text_logo：字、LOGO、牌匾（扁平类）

难度 / 体素分辨率（resolution_level）

basic：24×24×8（入门、儿童）

standard：32×32×12（常规，小摆件）

advanced：48×48×16（高细节、展示级）

风格（style）

pixel_plain：方正、平直、Minecraft 感强

pixel_round：层级圆润（适合人物）

chibi_big_head：大头身小

blocky_vehicle：硬朗车体

模板不是一张图，而是一个 3D 体素骨架 + 区域标记。

1.2 模板数据结构（核心：一个 JSON 规范）

给你一个工程师可直接用的 JSON 结构草案：

{
  "id": "char_basic_001",
  "name": "基础Q版人物-站立",
  "category": "character",
  "resolution": { "x": 32, "y": 32, "z": 12 },
  "difficulty": "basic",
  "style": "chibi_big_head",

  // 体素占用矩阵（可以用压缩形式存）
  "voxels": [
    // 每个体素记录位置 + 默认颜色槽
    { "x": 15, "y": 5, "z": 0, "slot": "leg" },
    { "x": 16, "y": 5, "z": 0, "slot": "leg" },
    { "x": 15, "y": 10, "z": 4, "slot": "body" },
    { "x": 16, "y": 10, "z": 4, "slot": "body" },
    { "x": 15, "y": 20, "z": 7, "slot": "head" }
    // ...
  ],

  // 语义区域 mask（方便后续贴图 / 调整体积）
  "regions": [
    { "name": "head", "z_range": [7, 11] },
    { "name": "body", "z_range": [3, 7] },
    { "name": "legs", "z_range": [0, 3] },
    { "name": "arms", "z_range": [3, 7] }
  ],

  // 参数化接口（后面算法可以按参数微调体积）
  "params": {
    "head_scale": { "min": 0.8, "max": 1.3, "default": 1.0 },
    "belly_scale": { "min": 0.8, "max": 1.5, "default": 1.0 },
    "leg_length": { "min": -2, "max": 3, "default": 0 }
  },

  // 颜色槽位：后续根据用户图像颜色自动填色
  "color_slots": {
    "skin": null,
    "hair": null,
    "cloth_primary": null,
    "cloth_secondary": null,
    "shoe": null
  },

  // 约束 & QC 规则（模板级常量）
  "constraints": {
    "min_support_neighbors": 2,
    "max_overhang": 1,
    "min_layer_area_ratio": 0.3
  }
}


上面你关心的几点：

voxels 里不是 RGB，而是 slot（语义颜色槽）
→ 后面才能把用户图片的颜色/区域 map 进去。

regions 让算法知道：哪一块是头、哪一块是肚子、哪一块是腿
→ 后面映射 2D 图时，不是整块馒头，而是“按身体区”贴。

params 让模板可变形
→ 同一套骨架，可胖可瘦、可大头可小头。

1.3 模板制作工作流（内部工具）

要有一个**“拼豆模板编辑器”**（内部用就好）：

设计师 / 工程师在 3D voxel editor 里搭出一个拼豆模型

标记各区域的 slot（head/body/legs/arms…）

指定可调参数（比如头高、肚子胖）

导出为符合上述 JSON 规范的模板文件

一开始模板可以少一点：
比如：char_basic_001 人物、animal_cat_001 小猫、house_basic_001 小屋、car_basic_001 小车。
模板只要 5–10 个，就足够你跑一个好玩的 MVP。

2. 算法工具链：从“用户图片”到“体素模型”

下面这部分就是你已经有一半雏形的东西，我帮你整理成完整链路。

2.1 Step 0：模式 & 模板选择

入口就不要太“AI 魔法”，让用户自己参与一点：

用户选：

模式：

「立体人物」/「立体动物」/「小房子」/「车辆」/「扁平牌匾」

或推荐：

根据图片轮廓比例（高宽比、占比）给出模板推荐

比如宽大扁平 → 更像车 / 房子

高且瘦 → 更像人物 / 动物

最终你得到：

chosen_template_id = "char_basic_001"
user_image = 上传图
user_params = { head_scale: 1.2, belly_scale: 1.4 ... }  // 可选

2.2 Step 1：图像预处理（你已有的可以保留）

前景 / 背景分割

PNG：透明通道

JPG：四角采样 + 色差判断 + 形态学清理

裁剪 & 缩放（保持比例）

把前景区域缩放到模板 resolution.x × resolution.y 的合适比例（预留一定边距）

生成前景 mask & 颜色图

fg_mask[x][y] = 0/1

img_color[x][y] = RGB 或 LAB

2.3 Step 2：语义区域映射（把 2D 图拆成头 / 身体 / 腿）

此处我们仍然尽量用规则，不用大模型，先走一个实用粗分法：

对于人物/动物模板，按 Y 方向截成三段：头/身/腿。

示例（32 像素高）：

0 ~ 10 行 → 头部候选区
10 ~ 22 行 → 上半身
22 ~ 32 行 → 腿/脚


再用一些“前景存在情况”微调分界线（比如某一段几乎为空，就略过）。

得到：

region_mask["head"][x][y] = 0/1
region_mask["body"][x][y] = 0/1
region_mask["legs"][x][y] = 0/1


这一层的精确度不需要完美，只要大致对即可。

2.4 Step 3：颜色槽匹配（把用户配色填到模板 color_slots）

对各个区域做简单颜色分析：

找头部区域的主色（皮肤） + 次主色（头发 / 帽子）

找身体区域主色（衣服主色） + 次色（衣服边）

找腿部（裤子 / 鞋）

然后映射到模板的：

"color_slots": {
  "skin": "#FAD1B0",
  "hair": "#4A2A1F",
  "cloth_primary": "#FF0000",
  "cloth_secondary": "#FFD000",
  "shoe": "#000000"
}


最后再做一层拼豆色板量化（Artkal / Hama / Perler 的色卡），映射成色号。

2.5 Step 4：生成 3D 体素模型（模板骨架 + 图像投影）

这里就是你算法层的核心了：

从模板 JSON 加载 voxels 列表：
每个体素有：(x, y, z, slot)

对每个体素 (x, y, z)：

查找该 (x, y) 在用户 2D 图中是否属于前景 fg_mask[x][y]

如果不是前景，可以：

要么删掉该体素（做出裁剪效果）

要么用默认结构保持（避免结构断裂）

根据 slot 决定颜色：

slot="head" → 用 color_slots.skin / hair 混合

slot="body" → 用 color_slots.cloth_primary

slot="legs" → 用 color_slots.shoe / cloth_secondary

根据用户选择/规则微调形状：

头部区域 → 应用 head_scale

躯干中段 → 应用 belly_scale

腿部 Z 方向 → 应用 leg_length

再结合一些“几何 hint”：

可以利用你之前提到的 distance transform 和骨架信息，

在同一 region 内，让靠「中心线」的体素多一些层数，边缘少一些层数 → 做出粗球 / 粗圆柱感。

最终输出：

voxel_model[x][y][z] = either { empty } or { color_index, region_slot }

2.6 Step 5：结构稳定性 & QC 检查（保证“能站、能拼”）

对 voxel_model 做一轮纯规则检查：

支撑检查

对每个 (x, y, z)，统计 z-1 层的支撑邻居数

少于模板 constraints.min_support_neighbors → 删除该体素或补足支撑

悬挑检查

如果某个体素所在位置，与下层的水平投影偏移大于 constraints.max_overhang → 收回

层面积检查

某层面积 < 下一层 × min_layer_area_ratio → 太尖 → 直接裁平高层

这一步的目标只有一个：

无论模板和图片怎么组合，最后出来的东西一定“可搭、会站、不乱裂”。

2.7 Step 6：切片 → 图纸 + 用料清单

这个你已经有一部分逻辑了，我们整理成体系：

对 Z 从 0 → Zmax：

生成一张二维网格图：

每个 (x, y) 是一个 “空 / 某色号”

渲染为：

PNG（带网格线 + 颜色块 + 可选色号文字）

或 SVG（方便放大打印）

导出多页 PDF：

每页一层（或 2–3 层）

左上角标注：Layer 3 / 12

右侧可以加“本层用料小计”：

颜色 A：N 颗

颜色 B：M 颗

全局用料统计：

汇总所有层的颜色用量

输出一张“材料清单”：

Color C01（肤色）： 128 颗
Color C09（黑色）： 54 颗
Color C23（红色）： 72 颗
...

            [稳定性QC：支撑/悬挑/层面积修正]

「图像预处理 & 区域粗分」之后，

在“体素模型生成”里把 depth 作为一个 depth_hint[x][y] 去混合使用。

4. 模板 + 算法的分工总结（方便和团队解释）

你可以这样对团队说（也方便对齐大家预期）：

模板负责：

三维结构骨架

哪里是头、哪里是身、哪里是腿

支撑逻辑、整体比例、体素分辨率

算法负责：

把用户的 2D 图“贴”到这些结构上：

轮廓 → 裁掉或保留体积

颜色 → 填进 color_slots

一点点局部起伏（用 distance + skeleton 做微调）

确保“不悬空、能站得住、能打印成图纸”

模型（未来如果有）只负责：

辅助给出：

哪块更凸

哪块更凹

最终是否采用，仍然由算法 & 模板说了算

5. 你接下来可以落地的几个“小目标”

为了不把这套体系变成“漂亮 PPT”，我给你建议几步非常实际的下一步：

先定 3–5 个模板 JSON（手工写/导出都行）：

char_basic_001：站立 Q 版人物

animal_cat_001：站立小猫

house_basic_001：小房子

car_basic_001：小车

badge_round_001：圆形徽章（扁平）

先实现一个“模板 + 硬裁剪 + 颜色贴图”的最小版本：

不做复杂 depth，只用模板的现有 voxels

只根据前景区域裁剪体素、填色

切层 + 出图纸

再逐步叠加：

belley/head_scale 这类简单参数

distance/skeleton 带来的球感、肚子鼓

稳定性 QC 规则
