# 拍照同步进度 Phase1 设计文档

## 状态
- 日期：2026-05-19
- 范围：客户端产品设计文档
- 阶段：设计完成，未进入实现
- 代码状态：不改业务代码、不 build、不发布

## 1. 背景与判断
之前的实时视觉辅助目标是让用户边拼边用摄像头识别进度，但真实场景里会遇到连续画面抖动、手遮挡、手机角度变化、光照变化、性能压力和浏览器摄像头权限等问题。这个方向技术风险高，且对手机稳定性要求很强。

本次新方向改为“拍照同步进度”：用户拼累后暂停，拍一张当前实物拼豆板照片上传，系统对照图纸判断已完成区域、疑似错放区域和不确定区域。用户确认后，系统把确认过的完成状态保存到制作页，下次继续制作时用灰度或半透明遮罩标出已完成部分，并显示剩余进度。

判断结论：这个方向值得做，而且比实时视觉辅助更适合作为第一批产品化能力。它把问题从“实时连续识别”降级为“单张照片识别 + 用户确认 + 进度保存”，技术风险和误判风险都更可控。

## 2. 产品定位
功能名称建议：
- 主入口名称：`拍照同步进度`
- 辅助说明：`上传实物照片，辅助判断已完成区域`
- 试验期标记：`试验`

产品承诺边界：
- 可以辅助用户估算完成度。
- 可以标记疑似错放位置。
- 可以把用户确认后的完成区域保存起来。
- 不承诺自动 100% 判定正确。
- 不自动覆盖用户已有进度。
- 疑似错误只做提示，最终由用户确认。

## 3. Phase1 目标
Phase1 只做可控闭环，不追求一步到位。

目标：
1. 用户能在制作页上传一张当前实物拼豆板照片。
2. 用户能指定或确认当前照片对应哪一块板。
3. 系统能识别照片中的板面四角，识别失败时允许用户手动校准。
4. 系统能对照当前板图纸输出格级识别结果。
5. 用户能在保存前预览识别结果。
6. 用户确认后，系统保存格级完成状态。
7. 制作页能用灰度/半透明遮罩显示已确认完成格。
8. 制作页能显示照片同步后的板内完成度和剩余数量。

## 4. Phase1 不做什么
Phase1 明确不做：
- 不做实时摄像头连续识别。
- 不做整张多板作品自动扫描。
- 不做跨多张照片自动拼接。
- 不做完全自动纠错和自动修改进度。
- 不做 AI 语义识别或云端视觉模型。
- 不强行改后端进度 API。
- 不修改手机端单板沉浸式手势模型、缩放边界、切板逻辑和冻结逻辑。

## 5. 用户流程
### 5.1 入口
建议入口放在单板制作模式的工具抽屉里：
- 按钮：`拍照同步`
- 次级说明：`识别实物完成度`
- 试验期可显示 `试验`

原因：
- 不常驻占用图纸空间。
- 符合当前手机端沉浸式“工具覆盖层”原则。
- 避免新功能破坏当前稳定的制作主流程。

### 5.2 上传照片
用户点击入口后进入弹层：
1. 选择照片或拍照上传。
2. 显示拍照建议：正对板面、尽量填满画面、避免强反光、保证边框完整。
3. 照片读取到 canvas 后进入校准步骤。

### 5.3 选择当前板
Phase1 默认使用当前正在制作的板。

如果作品是多板：
- 默认板：当前 activeBoard。
- 用户可以手动切换到其它板。
- 系统可以给出“可能是板 N”的建议，但不能自动无确认切换。

### 5.4 四角校准
系统先尝试自动识别板面四角。

结果分三档：
- `高可信`：直接进入识别预览，但允许用户微调。
- `中可信`：提示用户确认四角。
- `低可信/失败`：要求用户手动点选左上、右上、右下、左下。

校准完成后，系统按四边形插值把照片映射到图纸网格。

### 5.5 空孔参考色
现有识别算法需要知道“空板/空孔”的参考颜色，才能区分未完成格和已放豆格。Phase1 在四角校准后增加一个轻步骤：
- 如果当前板上能找到明显空孔，用户点击一个空孔作为参考。
- 如果用户照片里几乎已经拼满，允许用户点击板边未放豆区域或重新拍一张保留空孔的照片。
- 如果没有可靠空孔参考，系统可以进入预览，但必须降低质量等级，不允许一键同步。

### 5.6 识别结果预览
识别后显示四类格子：
- `已完成`：照片颜色与目标颜色匹配，置信度足够高。
- `疑似错误`：照片中有豆，但颜色更像其它颜色。
- `不确定`：受光线、反光、模糊、采样不稳影响，不能可靠判断。
- `未完成`：目标格为空或更接近空板颜色。

预览层建议：
- 已完成：半透明绿色或灰度遮罩。
- 疑似错误：红色细框或红点，不盖住色号。
- 不确定：黄色虚线或低透明提示。
- 低可信区域：在预览层用轻量斜纹或低透明黄点标出，并在摘要里说明原因，例如光线弱、反光、模糊或颜色距离过近。
- 未完成：不额外强调。

### 5.7 用户确认
保存前必须有确认步骤：
- 主按钮：`确认同步进度`
- 次按钮：`重新校准`
- 次按钮：`放弃`

确认说明：
`系统只是辅助识别，保存前请确认已完成区域是否正确。疑似错误不会自动改动你的图纸。`

### 5.8 写入制作进度
用户确认后保存：
- 当前板中用户确认过的 `confirmed_done` 格子。
- 本次照片同步时间。
- 识别质量摘要。
- 疑似错误和低可信区域的摘要数量。

保存后回到制作页：
- 已确认完成格显示灰度/半透明遮罩。
- 当前板显示照片同步进度。
- Phase1 不自动把整板标记为完成，也不把疑似错误或低可信区域写入完成状态。

## 6. 数据模型设计
现有 `boardStatusMap` 是板级完成状态，不适合直接承载格级进度。新功能需要独立格级状态，避免污染已有逻辑。

建议把“预览状态”和“持久化状态”分开。预览阶段可以展示疑似错误和低可信区域；持久化阶段只保存用户确认过的完成格，避免 AI 误判污染制作进度。

```ts
type PhotoProgressPreviewCellState =
  | "done_candidate"
  | "suspected_wrong"
  | "low_confidence"
  | "pending";

interface PhotoProgressPreviewCell {
  x: number;
  y: number;
  index: number;
  state: PhotoProgressPreviewCellState;
  confidence: number;
  targetColorId: string | null;
  detectedColorId: string | null;
  confidenceReasons: string[];
}

interface ConfirmedPhotoProgressCell {
  x: number;
  y: number;
  index: number;
  targetColorId: string | null;
  confidence: number;
  confirmedAt: number;
  source: "photo_upload";
}

interface ConfirmedPhotoProgressBoardSnapshot {
  boardNumber: number;
  boardSize: number;
  usedWidth: number;
  usedHeight: number;
  source: "photo_upload";
  createdAt: number;
  confirmedAt: number;
  qualityLevel: "good" | "warning" | "poor";
  completedCount: number;
  suspectedWrongCount: number;
  lowConfidenceCount: number;
  confirmedCells: ConfirmedPhotoProgressCell[];
}

interface PhotoProgressState {
  version: 1;
  projectId: string | number;
  beadDataHash: string;
  boards: Record<number, ConfirmedPhotoProgressBoardSnapshot>;
}
```

Phase1 保存策略：
- 本地优先，挂在现有制作页本地状态旁边。
- Phase1 只保存用户确认过的 `confirmedCells`。
- 疑似错误和低可信区域只保存摘要数量，不作为完成进度来源。
- 不覆盖 `boardStatusMap`。
- 如果用户之后手动点击“完成板”，板级完成仍然优先。
- 后续进入云同步时，再扩展后端 progress schema。

## 8. 识别可信度策略
Phase1 必须用“置信度”保护用户进度。

保存规则建议：
- 只有 `matched + confidence >= 阈值` 的格子可以进入 `done_candidate`。
- `wrong` 只进入 `suspected_wrong`，不自动改变完成状态。
- `qualityLevel = poor` 时禁止一键同步，只允许用户查看结果或重新拍照。
- 反光、模糊、采样异常或颜色距离过近的格子进入 `low_confidence`。

用户确认规则：
- 用户确认后，`done_candidate` 才转换为持久化的 `confirmed_done`。
- `suspected_wrong` 只保存摘要和预览提示，不计入完成度。
- `low_confidence` 不计入完成度。

## 9. 制作页显示规则
### 9.1 已完成遮罩
在单板制作图纸上，对 `confirmed_done` 格子显示轻灰或低透明遮罩。

显示原则：
- 不遮挡色号阅读。
- 不改变原图纸格子真实颜色数据。
- 高倍率下遮罩透明度降低，避免影响当前格判断。
- 当前选中格优先级高于完成遮罩。

### 9.2 疑似错误提示
疑似错误不常驻强提示，避免满屏红点干扰制作。

建议：
- 默认只显示少量摘要：`疑似错误 3 格`
- 用户点击后展开错误列表。
- 列表项显示：板号、行列、目标色、识别色。
- 点击列表项可定位到对应格。

### 9.3 进度展示
当前板：
- `照片同步：已确认 320/2916 格`
- `疑似错误 3`
- `不确定 12`

全作品：
- Phase1 不强行把格级进度并入当前板级完成百分比。
- 可以单独显示“照片同步进度”，避免和“板已完成”概念混淆。

## 10. 错误与异常处理
需要覆盖：
- 图片读取失败：提示重新选择。
- 图片过小/模糊：提示重新拍摄。
- 自动四角失败：进入手动四角校准。
- 照片不是当前板：提示用户切换板或重新选择。
- 识别质量差：禁止直接同步，允许查看。
- 本地保存失败：提示用户不要关闭页面，并允许重试。
- 图纸变化：如果 `beadDataHash` 不一致，旧照片同步进度不自动套用。

## 11. 测试计划
### 11.1 纯函数测试
放到 `TEST` 目录或现有测试体系中：
- 照片识别结果转换为格级进度状态。
- `confirmed_done / suspected_wrong / unknown` 统计。
- 低质量识别禁止一键同步。
- `beadDataHash` 不一致时不恢复旧进度。
- 板级完成状态与格级照片进度互不覆盖。

### 11.2 合成图片测试
用 canvas 生成测试拼豆板图片：
- 全部正确。
- 部分未完成。
- 单格错色。
- 多格错色。
- 边缘残板。
- 光照偏暗。
- 强反光区域。

验证：
- 识别能输出预期分类。
- 低质量图片不会误写完成状态。
- 疑似错误不会自动标记完成。

## 12. 风险等级
低风险：
- 新增设计文档。
- 新增独立上传弹层。
- 新增本地照片进度数据结构。
- 新增纯函数测试。

中风险：
- 复用 `visionAssistService.ts` 处理静态图片。
- 单板图纸上叠加完成遮罩。
- 本地状态恢复和清理。

高风险：
- 写入云端进度。
- 多板自动匹配并自动保存。
- 自动判错后影响用户制作流程。
- 将照片进度与板级完成状态强合并。

Phase1 应避免高风险项。

## 13. 分阶段实现建议
### Phase1-A：设计与数据基础
- 定义照片进度数据结构。
- 定义识别结果到进度状态的转换规则。
- 增加纯函数测试。
- 不接 UI。

### Phase1-B：上传照片识别弹层
- 新增上传照片入口。
- 静态图片进入 canvas。
- 当前板分析。
- 手动四角校准。
- 输出识别预览。
- 不写入制作页进度。

### Phase1-C：用户确认与本地保存
- 增加确认同步流程。
- 写入本地照片进度。
- 回到制作页后展示已完成遮罩。
- 疑似错误只做摘要提示。

### Phase1-D：真机验证与边界修复
- Android / iPhone 真机测试。
- 调整照片质量提示。
- 调整遮罩透明度。
- 只修复识别/显示边界，不扩展多板自动化。

## 14. 验收标准
Phase1 可以收口的标准：
1. 上传一张清晰单板照片，能完成识别预览。
2. 用户必须确认后才保存进度。
3. 保存后制作页能恢复已完成格遮罩。
4. 疑似错误不会自动写成完成。
5. 低质量照片不会误导用户一键同步。
6. 单板沉浸式图纸区域不被新功能挤压 layout。
7. 工具弹层打开时底层画布仍冻结。
8. 缩放、拖动、切板、复位无回归。
9. 桌面端、传统模式、多板非沉浸式不被污染。

## 15. Stop Condition
出现以下情况必须停止扩大范围：
- 单张照片识别经常把空格误判为完成。
- 完成遮罩明显影响色号阅读。
- 四角校准流程让用户无法理解。
- 保存进度后恢复不稳定。
- 新功能破坏当前手机端单板沉浸式交互。
- 用户需要大量手动修正，导致功能价值低于手动标记。

## 16. 当前建议
建议进入实现计划，但第一轮只写 Phase1-A / Phase1-B 的计划，不直接开发完整功能。

推荐第一批真正实现范围：
- 数据结构与转换纯函数。
- 静态照片识别弹层原型。
- 单板、当前板、手动四角校准。
- 识别预览。
- 暂不保存进度，先验证识别闭环。

确认识别闭环可用后，再进入用户确认保存和制作页遮罩。
