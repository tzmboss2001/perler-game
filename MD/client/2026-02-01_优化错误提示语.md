# 优化错误提示语

**日期**: 2026-02-01
**类型**: 用户体验优化

## 需求描述

原来的错误提示是技术性语言（如 "HTTP error! status: 404"），用户看不懂，需要改成人性化的提示语。

## 修改文件

### 前端
- `src/services/api/authApi.ts` - HTTP 状态码错误提示

### 后端
- `server/service/auth.go` - 业务逻辑错误提示

## 修改内容

### 前端 - HTTP 状态码映射

```typescript
const errorMessages: Record<number, string> = {
  400: '请求信息有误，请检查后重试',
  401: '登录已过期，请重新登录',
  403: '没有权限执行此操作',
  404: '服务暂时不可用，请稍后重试',
  500: '服务器开小差了，请稍后重试',
  502: '网络连接异常，请检查网络',
  503: '服务正在维护中，请稍后重试',
};
// 默认: '网络请求失败，请稍后重试'
```

### 后端 - 错误提示优化

| 场景 | 原提示 | 新提示 |
|------|--------|--------|
| 邮箱已注册 | "邮箱已被注册" | "该邮箱已注册，请直接登录" |
| 账户被禁用 | "账户已被禁用" | "该账户已被冻结，如有疑问请联系客服" |
| 密码错误 | "密码错误" | "密码不正确，请检查后重试" |
| 原密码错误 | "原密码错误" | "原密码不正确，请检查后重试" |
| 技术错误 | "密码加密失败"/"生成Token失败" | "登录遇到问题，请稍后重试" |
| 注册失败 | "注册失败: xxx" | "注册遇到问题，请稍后重试" |

## 效果

- 用户不再看到技术性错误信息
- 提示语更加友好、易懂
- 给出明确的操作建议（如"请检查后重试"、"请稍后重试"）
- 敏感信息不暴露（如不显示具体数据库错误）
