# 编辑页双指缩放误触发整页缩放修复

日期：2026-03-09
范围：客户端

## 问题

在编辑图案页面，用户用双指操作时，浏览器会把手势识别成整页缩放，而不是只缩放预览图，导致体验错误。

## 根因

- 编辑页的双指缩放逻辑只绑定在画布本身
- 当双指落点覆盖到画布边缘或预览容器区域时，浏览器仍可能接管默认的页面缩放手势
- 结果是用户想缩放图案，实际却缩放了整个页面

## 处理

在预览容器层补充原生多指手势拦截：

- 对容器的 `touchstart` 和 `touchmove` 添加非被动监听
- 仅在双指及以上触摸时阻止浏览器默认行为
- 补充 `gesturestart` / `gesturechange` 拦截，避免移动端浏览器接管页面缩放

这样单指滚动和编辑逻辑保留，双指缩放则优先交给图案预览本身。

## 修改文件

- `perler-beads/src/components/InteractiveCanvas.tsx`

## 验证

- 执行 `npm run build`，构建通过
- 发布到公网 `app-pd.shop888.vip`

## 结果

编辑页双指操作将不再触发整页缩放，而是优先作用于图案预览区域。
