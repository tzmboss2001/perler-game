# 创建图案与编辑图案单页化

日期：2026-03-09

## 问题

用户上传图片后，先进入“创建图案”页，再跳转到“编辑图案”页。两者本质上属于同一条创作链路，但被拆成两个独立页面，操作上显得重复、割裂，不够傻瓜化。

## 本次修改

1. `CreatePage` 在完成裁剪并点击生成后，不再跳转到 `/mobile/editor`。
2. `CreatePage` 改为在当前页面内部直接挂载 `EditorPage`，把上传图、网格宽度、颜色数量、自定义色板参数直接传入编辑器。
3. `EditorPage` 新增嵌入式用法：
   - 支持 `embeddedStateData`
   - 支持 `onBack`
4. 嵌入模式下点击左上角返回，或点击“返回选图”，会回到同一页内的上一步，而不是再走整页路由跳转。
5. 保留 `/mobile/editor` 旧路由能力，兼容历史入口、收藏链接和可能存在的其他调用。

## 用户可见变化

- 修改前：
  - 上传图片 -> 裁剪 -> 创建图案 -> 跳转到新页面“编辑图案”
- 修改后：
  - 上传图片 -> 裁剪 -> 创建图案 -> 直接进入同一页内的编辑流程

用户体感上会更像一个连续的“做图”流程，而不是被拆成两个产品页面。

## 涉及文件

- `perler-beads/src/pages/mobile/CreatePage.tsx`
- `perler-beads/src/pages/mobile/EditorPage.tsx`

## 验证

- 执行 `npm run build` 通过
- 编辑器仍保留独立路由用法，同时支持被创建页内嵌复用
