# 制作流程产品化 Phase1-B 实现范围与风险清单

日期：2026-05-18

## 当前基线

Phase1-A 已收口，当前稳定基线包括：

- 手机端单板沉浸式 layout 不占高；
- 当前板状态覆盖层；
- 当前色 / 当前格可读性；
- 高倍率选中格子的 overlay 遮挡修复；
- 轻量帮助入口复用单板新手引导；
- 工具抽屉打开时底层画布冻结；
- 手势、缩放、拖动边界、复位逻辑未改。

Phase1-B 必须建立在该基线之上，不重新定义沉浸式交互模型。

## Phase1-B 目标

Phase1-B 的目标不是继续增加大 UI，也不是重构制作页，而是把“制作帮助与冻结模型”从 Phase1-A 的轻量入口补齐为更明确、可测试、可回滚的产品化能力。

核心目标：

- 让用户在制作中能更容易理解单板模式关键操作；
- 帮助浮层打开时明确冻结底层画布；
- 帮助入口与工具抽屉关系清晰；
- 所有新增内容继续作为 overlay，不参与 layout 高度；
- 不破坏 Phase1-A 已验证的遮挡修复与沉浸式工作区。

## 具体实现范围

### 1. 帮助入口梳理

范围：

- 保留 Phase1-A 已存在的工具抽屉帮助入口；
- 明确帮助入口文案为“帮助”或“制作帮助”，避免和设置、辅助、图纸混淆；
- 如果设置面板内已有“制作帮助 / 查看”，继续复用同一个打开逻辑；
- 帮助入口只打开帮助 overlay，不触发切板、缩放、复位或导出。

不做：

- 不新增常驻大按钮；
- 不新增多个帮助入口；
- 不把帮助入口移到图纸核心区域；
- 不引入首次强制教学流程。

### 2. 帮助浮层产品化

范围：

- 继续使用现有单板引导内容作为基础；
- 优先把帮助内容拆成清晰的 3 到 4 条制作说明；
- 帮助浮层位置继续边缘化，优先底部或侧边卡片；
- 浮层必须可关闭；
- 点击浮层外空白关闭；
- 关闭后恢复原画布交互。

建议内容：

- 如何查看当前格 / 当前色；
- 何时可以滑动切板；
- 工具抽屉里有哪些高频功能；
- 完成本板后再切下一板，避免漏拼。

不做：

- 不做复杂多页教程；
- 不做动画教学；
- 不做手势轨迹演示；
- 不做横屏专用引导；
- 不接入用户学习进度云同步。

### 3. 冻结模型显式化

范围：

- 把帮助浮层纳入 `isSingleBoardInteractionLocked` 或等价锁定状态；
- 帮助浮层打开时，底层画布必须暂停响应拖动、缩放、切板和点格；
- 工具抽屉、设置面板、总览浮层、帮助浮层的冻结规则保持一致；
- 冻结逻辑优先抽到 `singleBoardInteraction.js` 的纯函数中测试。

不做：

- 不改现有手势优先级；
- 不改切板触发条件；
- 不改拖动边界；
- 不改缩放上下限；
- 不改复位视图。

### 4. 覆盖层视觉约束

范围：

- 帮助浮层必须是 absolute/fixed overlay；
- 不增加页面 padding、margin、safe-area 占位层；
- 不改变图纸容器高度；
- 不覆盖当前手指核心操作区域太久；
- 打开帮助时允许遮挡，因为此时底层画布已冻结；关闭后不得留下透明占位。

不做：

- 不改 Phase1-A detail-focus 弱隐藏策略；
- 不把底部工具栏重新变成 layout 流内容；
- 不引入 hidden 但仍占位的容器。

### 5. 测试与验收范围

必须补充：

- 单元测试：帮助打开时 interaction lock 为 true；
- 单元测试：非沉浸式或桌面端不因帮助状态锁死；
- 合同测试：帮助浮层仍是 overlay，不新增 layout 占高；
- MCP：手机端打开帮助后拖动画布，画布坐标不变；
- MCP：关闭帮助后，100% 到 200% 低中倍率微移仍正常；
- MCP：300% 以上自由拖动仍正常；
- MCP：多板切换不误触；
- MCP：桌面端、传统模式不受影响。

暂不要求：

- 不要求 build 前发布；
- 不要求正式域名验证；
- 不要求真机长测作为本阶段完成条件，但后续可以追加观察。

## 风险清单

### 中风险：冻结模型扩大

风险：

- 帮助浮层加入锁定条件后，可能误锁画布，导致关闭浮层后仍不能拖动或缩放。

控制：

- 锁定状态必须由纯函数计算；
- 明确 `helpOpen=false` 时恢复原有交互；
- MCP 必须验证关闭帮助后拖动、缩放、切板恢复。

回滚：

- 单独 revert Phase1-B 提交即可移除帮助锁定，不影响 Phase1-A。

### 中风险：覆盖层遮挡回归

风险：

- 帮助浮层或入口样式可能重新遮挡图纸边缘格子，破坏 Phase1-A 遮挡修复。

控制：

- 帮助入口只存在工具抽屉内；
- 帮助浮层打开时底层冻结，关闭后不留占位；
- 不改 detail-focus 的顶部/底部弱隐藏逻辑。

回滚：

- 回滚帮助浮层和入口，不回滚 Phase1-A 当前格/当前色逻辑。

### 中风险：MakingPage.tsx 继续膨胀

风险：

- Phase1-B 如果继续把大量帮助文案、状态和样式塞进 `MakingPage.tsx`，会增加后续维护成本。

控制：

- 本阶段只做最小帮助浮层；
- 不做组件大拆分；
- 如果实现过程中发现需要明显拆组件，停止并单独开重构 proposal。

回滚：

- Phase1-B 保持单提交或小提交，便于 revert。

### 低风险：文案理解偏差

风险：

- 帮助文案可能解释不清“何时能切板、何时不能切板”。

控制：

- 文案只解释现有规则，不改变规则；
- 使用短句说明：缩小到提示阈值附近、拖到边缘后才能切换相邻板；
- 不承诺任意倍率都能切板。

回滚：

- 可只改文案，不影响功能。

### 高风险：误碰手势系统

风险：

- 为了帮助或教学顺手改手势阈值、切板触发、拖动边界，会破坏 Phase1 稳定基线。

控制：

- Phase1-B 禁止修改手势阈值；
- 禁止修改 pan clamp；
- 禁止修改 reset view；
- 禁止修改 pinch / wheel / slider 缩放实现；
- 相关文件 diff 审查时必须重点检查。

回滚：

- 如果出现手势相关 diff，停止实现并撤回该部分，不进入测试。

## 建议文件范围

允许修改：

- `perler-beads/src/utils/singleBoardInteraction.js`
- `TEST/single_board_interaction.test.mjs`
- `TEST/mobile_immersive_visual_contract.test.mjs`
- `perler-beads/src/pages/mobile/MakingPage.tsx`
- `MD/client/*phase1b*.md`

暂不修改：

- `perler-beads/src/components/ExportModal.tsx`
- 生成质量相关服务；
- 色板数据；
- 后端 API；
- 发布脚本；
- 模板/社区相关页面。

## 建议提交策略

Phase1-B 建议最多拆成两个小提交：

- 提交 1：冻结模型纯函数与测试；
- 提交 2：帮助浮层产品化与 MCP 验收记录。

如果实际实现很小，也可以一个提交完成，但必须保证：

- diff 只覆盖 Phase1-B 范围；
- 自动测试通过；
- MCP 验证通过；
- MD 记录完整；
- 不发布正式域名。

## Stop Condition

出现以下任一情况，Phase1-B 应立即停止，不继续扩大改动：

- 图纸区域不再铺满标题栏以下空间；
- 工具或帮助浮层重新参与 layout 占高；
- 帮助关闭后画布仍冻结；
- 低中倍率微移失效；
- 300%+ 自由拖动失效；
- 多板切换出现误触；
- 传统模式或桌面端出现黑屏/不可操作；
- 出现需要改手势阈值才能完成帮助功能的情况。

## Phase1-B 完成标准

Phase1-B 只有在以下条件都满足时才算完成：

- 帮助入口清楚且不新增核心区遮挡；
- 帮助浮层打开时底层画布完全冻结；
- 帮助浮层关闭后原交互恢复；
- overlay-only 合同测试通过；
- `single_board_interaction` 测试通过；
- `mobile_immersive_visual_contract` 测试通过；
- `npm run build` 通过；
- MCP 手机端、桌面端、传统模式、多板模式验收通过；
- 工作区干净；
- 本阶段 MD 记录完成。

## 当前结论

Phase1-B 可以进入实现准备，但第一步应只做冻结模型纯函数与测试，不应直接改 UI。实际编码前继续保持 TDD：先补失败测试，再写最小实现。
