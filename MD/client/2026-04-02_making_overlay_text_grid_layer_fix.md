# 2026-04-02 制作模式高清覆盖层修复

## 问题
上一次为了解决制作模式高倍率黑屏，引入了“底图安全渲染 + 外层视觉缩放”的方案，但副作用是：
1. 格子里的色号会随视觉缩放一起被放大并发糊。
2. 网格线、板线和中心十字也会跟着底图一起模糊。
3. 用户感知上变成了“解决了黑屏，但牺牲了制作清晰度”。

## 根因
此前的实现里，底图、网格、板线、板号和色号都仍然依附在同一张主 canvas 上。即使内部渲染做了安全限流，外层 CSS scale 仍会把这些文字和线条一起放大，从而丢失清晰度。

## 修复方案
将制作模式渲染拆成两层：
1. 底图层：继续使用主 canvas，按安全尺寸渲染珠子颜色和暗化效果，避免大图高倍率黑屏。
2. 高清覆盖层：新增独立 overlay canvas，按当前屏幕像素和当前视口直接重绘：
   - 基础小格线
   - 现实拼豆板内部对称分区线
   - 豆板边界线
   - 中心十字
   - 板号标签
   - 当前板聚焦边框
   - 当前区块边框
   - 格内色号

## 关键实现
- 在 `MakingPage.tsx` 中新增 `overlayCanvasRef`。
- 主 canvas 的渲染 effect 中移除网格/板号/色号绘制，只保留底图和暗化层。
- 新增独立 overlay 渲染 effect：
  - 直接依据 `scale`、`translateX`、`translateY` 和 wrapper 尺寸，计算可视区域。
  - 只绘制当前视口内需要显示的线条和色号。
  - 线条按像素对齐绘制，避免 1px 细线发虚。
  - 色号使用等宽字体并描边，按屏幕可见字号封顶，不再无限膨胀。
- 在 DOM 中给制作画布增加绝对定位的 overlay canvas，`pointer-events: none`，不影响交互。

- `npm run build` 通过。
- MCP 实测制作模式页面恢复正常，不再因 `focusedBoardRect is not defined` 报错黑屏。

  - `TEMP/making_overlay_zoom600_fixed.png`

## 当前效果
- 黑屏问题的修复方向保留：底图仍走安全渲染。
- 清晰度问题不再靠牺牲文字和网格解决，而是通过高清覆盖层恢复：
  - 色号和网格与底图解耦
  - 高倍率时文字与线条仍保持清晰
  - 不再随着底图一起被 CSS scale 放糊
