# 2026-03-30 最大宽度保存前端传输压缩移除

## 背景
- 编辑图案页在最大宽度 `240` 下保存方案时，图片上传可以成功，但方案创建请求常出现长时间停留在保存中。
- 真实链路检查发现，部分场景下 `project/create` 在网络层没有及时发出，瓶颈更像卡在前端保存前的 bead_data 压缩/序列化阶段。

## 本次修改
- 文件：`perler-beads/src/services/api/projectApi.ts`
- 移除浏览器端 `gzip + base64` 传输压缩。
- 云端保存改为只发送精简后的 `bead-id-grid-v1` 颜色 ID 网格。
- 服务端继续负责入库压缩，因此前端只做轻量 compact，不再在主线程做重压缩。

## 目的
- 降低最大宽度保存时前端主线程负担。
- 让 `project/create` 更快进入真实网络请求阶段。
- 避免保存长时间停留在“保存中...”且无法进入制作模式。
