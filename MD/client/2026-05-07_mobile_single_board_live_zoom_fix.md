# 2026-05-07 单板制作模式实时缩放修复记录

## 问题

在单板制作模式中，双指缩放图纸区域或拖动缩放滑杆时，图纸没有跟随手势或滑杆实时放大/缩小，而是在停止操作后才跳到最终倍率。

## 根因

缩放输入会实时更新目标倍率 `scale`，但即时 CSS transform 使用了根据目标倍率计算出来的“预测渲染倍率”。当目标倍率从 `1` 变为 `1.5` 时，预测渲染倍率也变为 `1.5`，导致即时显示倍率被计算为 `1.5 / 1.5 = 1`，视觉上等于没有放大。

触摸设备还保留了 `140ms` 的高清重绘延迟保护，连续缩放时该延迟会不断重置，所以用户看到的是停止操作后才更新。

## 修复

- 新增 `getLiveStageDisplayScale`，明确即时视觉缩放必须基于当前已绘制的 `renderScaleRef.current`。
- `commitTranslate` 立即更新画布容器 transform 时，不再使用预测渲染倍率抵消目标倍率。
- 高清重绘仍使用原有延迟和安全渲染预算，避免 iPhone / 触摸设备在缩放过程中创建过大的 canvas。
- 色号覆盖层继续用 live transform 过渡，保持与底图同步。

## 影响范围

- 影响：单板模式双指缩放、缩放滑杆、加减按钮、桌面滚轮缩放。
- 不影响：后端 API、保存方案、登录、社区作品、传统模式的数据逻辑。
- 传统模式共用缩放管线，预期只获得实时跟手改进，不改变缩放上下限。

## 验证

- `node --test TEST\single_board_interaction.test.mjs`：41/41 通过。
- `npm run build`：通过。
- MCP 本地验证：
  - 页面：`http://127.0.0.1:3009/mobile/making`
  - 操作：把缩放滑杆从约 `141%` 调到约 `221%`
  - 即时结果：画布可视宽高从 `225px` 变为 `353px`
  - 停止后：高清 canvas 尺寸追平为 `353px`，视觉尺寸不再二次跳变

## 测试建议

- 在手机端进入单板制作模式，双指连续放大/缩小，观察图纸是否跟手连续变化。
- 拖动缩放滑杆，观察图纸是否在拖动过程中实时变化。
- 停手后观察是否只发生清晰度细化，不再发生图纸尺寸跳变。
- 抽测传统模式缩放、加减按钮和滚轮缩放，确认没有回归。
