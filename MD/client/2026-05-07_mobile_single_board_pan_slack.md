# 手机端单板沉浸式低中倍率上下拖动余量

## 问题

手机端单板沉浸式后，图纸工作区高度明显变高。原来的拖动边界按 `canvasHeight <= wrapperHeight` 时把 Y 方向偏移固定为 0，导致 100%-200% 这类画布高度小于工作区的倍率下，只能左右移动，不能上下微调画面。

根本原因属于前端画布位移边界策略，不是后端、接口或配置问题。

## 修改

- 新增 `clampMakingStageTranslate`，统一计算制作画布位移边界。
- 普通模式仍保持原规则：画布小于工作区时 Y 方向不能移动。
- 仅手机端单板沉浸式启用保守的 Y 方向自由余量：`min(120px, 工作区高度 * 15%)`。
- 画布高度大于工作区时仍使用正常画布边界，不叠加额外余量。
- 单板切板判断单独使用无沉浸式余量的边界，避免低中倍率上下微移误触发切板。

## 回归范围

- 100%、150%、200%：允许上下轻微平移，但不会无限拖出视野。
- 300% 以上：画布大于工作区后按正常边界任意方向拖动。
- 工具抽屉打开时：底层画布交互保持冻结。
- 多板切换：新增余量不参与切板边界判断，降低误切风险。
- 复位视图：仍回到居中合理位置。

## 验证

- `cmd /c node --test TEST\single_board_interaction.test.mjs`
- `cmd /c npm.cmd run build`

## MCP 手机视口回归

- 390x844 移动视口，单板沉浸式 100%：上下拖动可到 `y=±118.68px`，未超过 `min(120px, 高度15%)`。
- 149% 与 199%：同样可上下轻微平移，边界仍限制在 `±118.68px`。
- 329%：画布大于工作区后，对角拖动得到 `x=220px, y=97.15px`，按正常画布边界移动。
- 工具展开后拖动画布：位移保持 `x=0, y=0`，底层画布被冻结。
- 160x160 多板测试图，35% 切板手势区内首次竖向拖动：`activeBoardNumber` 仍为 1，未出现“已切到板”提示，先执行平移不误切。
- 双指缩放事件：合成触摸 pinch 将滑杆从 `0.35` 推到 `0.8`，缩放链路仍响应。
- 复位后：位移回到 `x=0, y=0`。
