# 2026-03-04 第2项优化：发布前质量闸门

## 目标
建立可执行的前端发布前质量闸门，覆盖：
1. 构建失败阻断
2. 关键路由冒烟检查
3. 乱码风险增量拦截（基线对比）

## 本次改动
1. 新增脚本
- `SCRIPT/frontend_quality_gate.ps1`
- 逻辑：
  - `frontend_build`: 执行 `npm run build`，失败即退出
  - `frontend_dev_smoke`: 启动 dev server，检查 `/` `/mobile/home` `/mobile/create` `/mobile/profile` `/mobile/login` 均返回 200
  - `frontend_garbled_diff`: 对核心页面文件做乱码特征扫描，和基线文件比对，只拦截“新增乱码”
  - 输出报告到 `TEMP/quality_gate_report.md`

2. 增加 npm 命令
- `perler-beads/package.json`
  - `quality:gate`
  - `quality:gate:update-baseline`

3. 生成基线文件
- `TEST/quality_gate_garbled_baseline.txt`
- 用于控制历史存量问题，不阻塞当前发版；新增问题会被门禁拦截。

## 验证
执行结果：
- `npm.cmd run quality:gate:update-baseline`：完成
- `npm.cmd run quality:gate`：通过
- 报告：`TEMP/quality_gate_report.md`
  - `frontend_build: PASS`
  - `frontend_dev_smoke: PASS`
  - `frontend_garbled_diff: PASS`

## 备注
- 当前基线内仍有少量历史乱码命中（存量），门禁策略为“阻断新增，不放大旧债”。
- 下一步可逐批清理基线项，达到全量零乱码标准。
