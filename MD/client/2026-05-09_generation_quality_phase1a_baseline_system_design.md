# 生成质量优化 Phase1-A：质量基准系统设计

## 阶段结论

Phase1-A 的目标，是先建立“如何稳定判断生成结果好坏”的基准体系。

本阶段不写算法代码，不改制作交互，不进入模板、社区、作品体系等平台化扩展，不做复杂自动评分系统。

核心原则：

- 不能只看单张成功案例。
- 必须用固定样张、固定参数、固定输出结构做横向比较。
- 每次优化都要能回答：整体是否提升，核心样张是否有明显回退，变化原因是否可解释。

## 背景

当前《生成质量优化 Phase1 设计文档》已经确认生成质量是下一阶段主线，commit 为：

- `5712705c docs: add generation quality phase1 design`

Phase1-A 是 Phase1 的第一步：质量基准系统。

它不直接优化减色、色板映射、轮廓或防脏色，而是先建立后续优化必须依赖的比较基础。

没有质量基准系统，算法调整容易出现三个问题：

- 只对当前手上的一张图变好，其他图退化。
- 视觉上似乎更干净，但主体识别度下降。
- 很难解释问题来自色板、减色、尺寸、轮廓、背景还是库存限制。

## 阶段范围

Phase1-A 覆盖：

- 固定样张集结构。
- 批量生成与结果归档方案。
- before/after 对比输出方式。
- 问题标签体系。
- 质量评分与验收流程。
- 色板与减色等级测试矩阵。
- 回归比较机制。
- 目录与元数据规范。

Phase1-A 不覆盖：

- 不改 `pixelizeService`、`colorMatchService` 等生成算法。
- 不改 `MakingPage` 和手机端单板沉浸式制作交互。
- 不改模板、社区、收藏、云端作品体系。
- 不接入复杂自动评分模型。
- 不要求第一阶段接入后端数据库。
- 不要求第一阶段自动判定所有主观质量问题。

## 设计目标

1. 建立稳定基准。
   同一批样张、同一组参数、同一版本算法，可以重复生成可比较结果。

2. 建立质量语言。
   所有人讨论生成质量时，使用统一问题标签，而不是只说“好看”“不好看”。

3. 建立可比较体系。
   每次优化都有 before/after，对比图、参数和质量标签都能追溯。

4. 建立回归机制。
   新策略不能只让单张图变好；必须检查核心样张是否退化。

5. 控制阶段复杂度。
   Phase1-A 先保持轻量，先用人工质量标签 + 基础统计，不做过重自动评分。

## 固定样张集结构

Phase1-A 样张集先保持轻量：8 类，每类 2 张，共 16 张。

样张类别：

1. `portrait`：人像头像。
   验证肤色、头发、五官、脸部轮廓和背景分离。

2. `pet`：宠物。
   验证毛发、眼睛、鼻子、深浅毛色和主体边缘。

3. `cartoon`：卡通图。
   验证纯色块、黑线、边界连续性和色彩稳定性。

4. `complex-photo`：复杂照片。
   验证背景干扰、颜色碎片、低对比区域和脏色控制。

5. `logo-text`：Logo 或文字。
   验证硬边、文字可读性、对比度和小尺寸识别。

6. `low-resolution`：低清晰度图片。
   验证模糊输入、小图锐化、噪点放大和主体识别。

7. `high-saturation`：高饱和图片。
   验证强饱和色、色彩过冲和色板映射偏移。

8. `light-subject`：浅色主体加浅色背景。
   验证轮廓保护、背景污染和主体边界增强。

样张命名建议：

```text
<category>_<index>_<short-name>.<ext>
```

示例：

```text
portrait_01_girl.png
pet_02_white-dog.jpg
logo-text_01_red-logo.png
```

## 样张元数据

每张样张需要在 `samples.json` 中登记。

建议字段：

```json
{
  "id": "portrait_01_girl",
  "category": "portrait",
  "file": "samples/portrait/portrait_01_girl.png",
  "description": "浅色背景人像头像，包含肤色、头发和五官",
  "primaryRisks": ["skin_shift", "small_detail_blur", "outline_lost"],
  "subjectType": "human",
  "defaultCrop": "subject-centered",
  "notes": "用于验证默认 MARD 221 标准档是否保住五官"
}
```

字段原则：

- `id` 必须稳定，后续报告和回归都引用它。
- `primaryRisks` 用于提前标记这张图主要验证什么问题。
- `notes` 记录人工判断背景，避免后续误读样张意图。

## 测试矩阵

Phase1-A 不做过重矩阵，先用最小可用矩阵。

核心矩阵：

- 样张：16 张。
- 色板：MARD 221、MARD 291、用户库存色板。
- 减色等级：标准、简化。
- 尺寸：54×54。

核心结果数：

```text
16 × 3 × 2 × 1 = 96
```

这个规模足够暴露主要问题，同时不会让第一阶段被测试量拖死。

扩展矩阵后置：

- 减色等级补充：细致、极简。
- 尺寸补充：32×32、108×108。
- 样张补充：每类增加到 4-5 张。

扩展矩阵不作为 Phase1-A 第一轮完成条件。

## 色板维度

Phase1-A 至少覆盖三类色板。

### MARD 221

默认推荐色板，用于验证普通用户最可能使用的生成结果。

关注点：

- 主体是否清楚。
- 颜色数量是否可控。
- 是否适合真实购买和制作。

### MARD 291

高级细节色板，用于验证全色方案是否能带来合理细节提升。

关注点：

- 细节是否更好。
- 是否引入过多碎色。
- 与 MARD 221 的差异是否可解释。

### 用户库存色板

制作优先色板，用于验证库存不足时的质量边界。

关注点：

- 只用库存色时是否严重偏色。
- 缺失色和替代色是否可解释。
- 是否需要明确质量风险提示。

## 减色等级维度

Phase1-A 首轮只必测两档：

1. 标准。
   默认用户最常用档位，用于判断整体生成质量。

2. 简化。
   用于判断减少颜色后是否更容易制作，以及主体是否仍可识别。

后续扩展：

- 细致：验证复杂图和大图细节。
- 极简：验证儿童、Logo、图标和低复杂度作品。

## 结果归档方案

每一次基准运行都要生成独立 `run-id`。

建议格式：

```text
YYYYMMDD-HHMM-<short-commit>-<matrix-name>
```

示例：

```text
20260509-2130-5712705c-phase1a-core
```

每个结果保存：

- 输入样张。
- 生成图。
- 参数 JSON。
- 用色统计。
- 缺失库存色。
- 替代色。
- 问题标签。
- 总体质量等级。
- 运行环境信息。

建议单个结果元数据：

```json
{
  "sampleId": "portrait_01_girl",
  "runId": "20260509-2130-5712705c-phase1a-core",
  "commit": "5712705c",
  "paletteMode": "mard-221",
  "paletteVersion": "mard-221",
  "simplifyLevel": "standard",
  "size": { "width": 54, "height": 54 },
  "actualColorCount": 42,
  "missingInventoryColors": [],
  "replacementColors": [],
  "qualityGrade": "acceptable",
  "issueTags": ["small_detail_blur"],
  "reviewNotes": "五官可识别，但眼睛略糊"
}
```

## 对比输出方式

Phase1-A 的对比输出要服务人工判断。

建议每次运行生成三类输出：

1. 单样张对比。
   展示原图、当前基线结果、新结果、色板、减色等级、用色数量和问题标签。

2. 分类汇总。
   按人像、宠物、卡通等类别汇总 pass、acceptable、fail 数量。

3. 回归摘要。
   展示新结果相对基线的变化：提升、持平、退化。

对比页可以后续实现为 HTML，但 Phase1-A 设计阶段只定义输出要求。

对比页必须避免只展示成功样张，应展示完整矩阵结果。

## 问题标签体系

问题标签用于统一质量语言。

总体等级：

- `pass`：可以继续制作。
- `acceptable`：有瑕疵，但主体清楚，仍可制作。
- `fail`：不建议制作。

问题标签：

- `identity_lost`：主体不像或关键特征丢失。
- `dirty_colors`：脏色明显。
- `outline_lost`：主体轮廓丢失。
- `too_fragmented`：颜色太碎，孤立珠过多。
- `small_detail_blur`：小图细节糊。
- `palette_shift`：色板映射偏色。
- `inventory_insufficient`：用户库存色不足。
- `not_makable`：理论可看，但实际难拼。
- `background_pollution`：背景污染主体。
- `over_simplified`：简化过度，主体信息不足。
- `over_detailed`：细节过多，制作成本过高。

标签原则：

- 一个结果可以有多个问题标签。
- `fail` 必须至少有一个问题标签。
- 标签要描述原因，不能只描述感受。

## 质量评分流程

Phase1-A 不做复杂自动评分。

推荐使用人工等级 + 基础统计的方式。

人工等级：

- `pass`
- `acceptable`
- `fail`

基础统计：

- 实际颜色数量。
- 单颗孤立珠数量。
- 最大连续色块占比。
- 缺失库存色数量。
- 替代色数量。
- 色板模式。
- 减色等级。

人工判断优先，基础统计辅助解释。

例如：

- 如果颜色数量降低，但 `identity_lost` 增加，则不算有效提升。
- 如果脏色减少，但轮廓丢失，则需要标记为局部提升但整体不可接受。
- 如果 MARD 291 颜色更多但 `too_fragmented` 明显增加，需要说明全色方案带来的制作成本。

## 回归比较机制

每次后续算法改动都必须与最近稳定基线比较。

比较结果分四类：

- `improved`：明显提升。
- `unchanged`：基本持平。
- `regressed`：明显退化。
- `mixed`：有提升也有退化，需要人工判断是否接受。

接受规则：

- 核心样张不能出现明显退化。
- `fail` 数量不能增加。
- 人像、宠物、卡通、Logo 四类核心样张不能从 `acceptable` 降为 `fail`。
- 单张图提升不能抵消多张图退化。
- 如果出现退化，必须记录原因并决定回滚、调整或拆分优化策略。

## 验收流程

后续每次算法优化进入验收时，按以下顺序：

1. 固定样张和测试矩阵。
2. 生成当前基线结果。
3. 应用单一优化策略。
4. 重新批量生成。
5. 输出 before/after 对比。
6. 标记每张图质量等级和问题标签。
7. 生成汇总报告。
8. 判断是否整体提升。
9. 检查核心样张是否明显回退。
10. 决定接受、回滚或继续拆分。

验收结论必须能追溯到具体样张和具体问题标签。

## 最小可用完成标准

Phase1-A 后续实现完成时，应至少满足：

- 16 张固定样张完成登记。
- 核心测试矩阵定义完成。
- 能生成 96 个结果的参数清单。
- 每个结果有元数据记录。
- 能按样张输出 before/after 对比。
- 能记录 `pass`、`acceptable`、`fail`。
- 能记录问题标签。
- 能汇总各类样张的通过、可接受、失败数量。
- 能识别新增退化项。
- 不影响现有制作模式和手机端单板沉浸式交互。

## 风险与控制

风险一：样张过少，代表性不足。

控制：Phase1-A 先用 16 张建立机制，后续再扩展样张数量，不在第一轮追求完美覆盖。

风险二：人工标签主观。

控制：统一标签含义，失败必须写原因，核心样张反复复用。

风险三：矩阵过大拖慢推进。

控制：首轮只跑 96 个核心结果，扩展矩阵后置。

风险四：统计指标误导判断。

控制：基础统计只做辅助，不替代人工质量判断。

风险五：优化范围蔓延到制作交互。

控制：Phase1-A 只做生成质量基准，不改制作模式、不改沉浸式交互。

## 后续拆分建议

Phase1-A 后续可拆成三个实现子任务：

1. 样张与矩阵规范落地。
   建立样张目录、样张 manifest、核心测试矩阵。

2. 批量生成与归档工具。
   生成结果、参数、用色统计和元数据。

3. 对比报告与质量标签流程。
   输出 before/after 对比和人工质量标签汇总。

这三个子任务应独立提交，方便回滚和定位问题。
