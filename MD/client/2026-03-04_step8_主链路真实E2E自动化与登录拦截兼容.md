# 2026-03-04 Step8 主链路真实E2E自动化与登录拦截兼容

## 问题现象
- 新增的主链路 E2E（Create -> Editor -> Making）在自动化执行时不稳定，主要卡在：
  1. 裁剪页“确认”按钮可见但点击被覆盖层拦截。
  2. 进入 Editor 后“保存并开始制作”在未登录态会走登录提示，自动化无法继续。

## 根因
- `ImageCropper` 容器层级 `zIndex: 1100`，低于引导层（`OnboardingGuide` 9999 / `OnboardingModal` 10000），导致裁剪确认点击可能被遮挡。
- `EditorPage` 的“开始制作”默认要求登录；原有 `Shift+点击` 测试通道在无头自动化下触发不稳定。

## 本次改动

### 1) 修复裁剪层级冲突
- 文件：`perler-beads/src/components/ImageCropper.tsx`
- 改动：`styles.container.zIndex` 从 `1100` 提升为 `11001`。
- 作用：确保裁剪层在引导层之上，自动化和手动点击都更稳定。

### 2) 增加开发环境 E2E 登录绕过开关（仅 DEV 生效）
- 文件：`perler-beads/src/pages/mobile/EditorPage.tsx`
- 新逻辑：
  - 新增 `e2eBypassLogin`：`import.meta.env.DEV && window.__E2E_BYPASS_LOGIN__`
  - 未登录拦截条件改为：`!isLoggedIn && !e2eBypassLogin`
  - 直达制作条件改为：`e?.shiftKey || e2eBypassLogin`
- 作用：线上行为不变；本地/测试环境可稳定自动化通过主链路。

### 3) 完善真实 E2E 脚本
- 文件：`TEST/mobile_main_flow_e2e.mjs`
- 改动：
  - 增加容错点击（普通点击 -> 强制点击 -> DOM click）。
  - 增加引导“跳过”自动处理。
  - 增加失败时按钮文本与截图诊断。
  - 注入 `window.__E2E_BYPASS_LOGIN__ = true` 以稳定通过 Editor 未登录拦截。

### 4) 修复 E2E 执行封装日志
- 文件：`TEST/mobile_main_flow_e2e.ps1`
- 改动：直接管道 `node` 输出到 `Tee-Object`，保证执行日志可落盘。
