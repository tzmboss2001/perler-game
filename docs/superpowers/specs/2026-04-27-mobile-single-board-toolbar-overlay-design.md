# 手机端单板模式按钮条遮挡图纸修复设计

## 背景

真机反馈表明，手机端单板制作模式下，首屏用于 `总览 / 复位 / 完成 / 工具` 的四按钮条会遮挡部分图纸。当前实现里，图纸画布容器仍沿用固定 `top` 偏移，而顶部实际已经叠加了：

- 模式切换条
- 单板进度摘要
- 四按钮工具条

结果是图纸工作区的起始位置没有按真实工具区高度同步下移，视觉上出现“按钮挡住图纸”。

## 目标

- 不再让手机端单板模式工具条遮挡图纸。
- 保留高频操作的可达性，不把核心按钮全部藏起来。
- 尽量把首屏更多高度还给图纸。
- 不破坏桌面端侧边栏布局，也不回退手机端上一轮首屏收薄优化。

## 推荐方案

采用“动态避让 + 半浮动可折叠工具条”。

### 1. 动态避让

图纸容器不再使用写死的 `top` 值，而是根据手机端单板模式顶部真实占高动态计算可用画布区。

需要纳入计算的区域：

- 模式切换条
- 单板进度摘要
- 四按钮工具条
- 需要时的滑动切板状态提示

目标是先彻底消除“按钮压在图纸上”的问题，即使工具条仍完全展开，也不能再覆盖图纸。

### 2. 半浮动工具条

在手机端单板模式下，把现有四按钮条改成更薄的半浮动条：

- 默认展开时仍显示：
  - `总览`
  - `复位`
  - `完成`
  - `工具`
- 但按钮高度、内边距、字体、外边距都进一步压缩。
- 整条工具条视觉上与图纸区脱开，不再像“实体占位块”。

### 3. 自动收起

当用户开始操作图纸时，工具条自动收成更轻的状态：

- 触发时机：
  - 开始拖动画布
  - 开始缩放
  - 单击图纸进行选区/选色
- 收起后的形态：
  - 保留一个很薄的浮动入口
  - 或保留当前板最关键操作的极简条

再次点击入口或停止操作后，可重新展开完整四按钮条。

## 交互细节

### 展开态

- 首次进入单板模式时默认展开，保证用户可发现性。
- 展开态下：
  - 高度比当前版本更薄
  - 不遮挡图纸
  - 与顶部摘要区之间留更小间距

### 收起态

- 收起态不应完全消失，避免用户找不到工具。
- 收起入口建议保留在图纸上方安全区，避免遮住正在制作的格子。
- 入口文案或图标以 `工具` 为主，不引入新术语。

### 展开/收起状态记忆

- 只在当前会话内记忆即可。
- 不需要写入长期本地存储，避免把临时状态带到下次进入制作页。

## 技术设计

### 新增 helper

在 `singleBoardInteraction.js` 中新增专门用于手机端单板顶部布局的 helper，统一计算：

- 顶部真实避让高度
- 工具条是否处于收起态
- 展开态与收起态的尺寸参数

避免在 `MakingPage.tsx` 里散落大量手机端单板特判。

### `MakingPage.tsx` 调整

- 用 ref 测量顶部单板摘要区和工具条实际高度。
- 将 `canvasWrapperStyle.top` 改成动态值，而不是固定 `46px`。
- 四按钮条改成：
  - 展开态样式
  - 收起态样式
- 绑定自动收起触发逻辑，但不影响桌面端和传统模式。

## 风险与约束

### 风险 1：按钮可发现性下降

通过“首次展开 + 收起后保留入口”控制风险，避免用户误以为功能消失。

### 风险 2：误收起影响高频操作

自动收起只在用户已经明确进入图纸操作后触发；页面初始和短暂停留不自动收起。

### 风险 3：桌面端回归

这轮只改 `isSingleBoardMobile && viewMode === "singleBoard"` 分支，桌面侧边栏布局保持不变。

## 验证标准

### MCP / 本地验证

- 手机口径单板模式下，图纸不再被按钮条遮挡。
- 展开态四按钮条仍可用。
- 触发拖动/缩放后，工具条会自动收薄或收起。
- 再次点击入口后，可恢复完整四按钮条。

### 真机验收

- 真机首屏进入单板模式时，不再出现按钮压在图纸上的情况。
- 用户仍能快速找到：
  - 总览
  - 复位
  - 完成
  - 工具
