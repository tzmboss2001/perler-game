# 移动端沉浸式制作 Phase2 第一轮体验优化设计

## 状态

手机端单板沉浸式制作模式 Phase1 已完成并冻结。本设计只定义 Phase2 第一轮低风险体验优化，不进入开发实现。

本轮目标不是新增功能，也不是重新调整交互模型，而是在不破坏 Phase1 稳定基线的前提下，提升移动端单板制作模式的专业感、顺滑感、视觉层级和沉浸感。

## 本轮范围

Phase2 第一轮只做三类低风险优化：

- 浮层视觉层级。
- 状态提示视觉。
- 基础动画过渡。

本轮明确不做以下内容：

- 横屏沉浸式。
- 多板沉浸式。
- 手势阈值调整。
- FAB 位置持久化。
- 高级辅助交互。
- 新手引导流程。
- 工具抽屉结构重构。
- 画布拖动边界重算。

## Phase1 不变量

本轮任何视觉和动画改动都必须保持以下不变量：

- 只影响手机端单板沉浸式制作模式。
- 桌面端、传统模式、非沉浸式多板模式不受影响。
- 图纸区域仍必须铺满标题栏以下空间。
- 工具、缩放、状态和辅助入口仍必须是覆盖层，不能重新参与 layout 占高。
- 不能出现 hidden 但仍占 layout 高度的工具栏、状态栏、缩放栏或透明占位层。
- 工具抽屉、设置面板、总览层打开时，底层画布拖动、缩放、点击和切板必须冻结。
- 100%-200% 低中倍率上下微移策略保持不变，余量仍为 `min(120px, 工作区高度 * 15%)`。
- 300% 以上画布大于工作区时，仍按正常画布边界支持自由拖动。
- 多板图纸切板逻辑保持不变，不能因为视觉浮层或动画导致误切板。
- 复位视图仍回到当前板的合理中心位置。
- 状态提示只能出现在顶边、底边或边缘位置，不能漂浮在图纸中心长期遮挡格子。

## 设计原则

- 视觉优先，但不改变交互语义。
- 动画只使用 `opacity`、`transform`、`filter` 等不会触发布局重排的属性。
- 不改变按钮点击区域，不改变事件绑定，不改变指针事件优先级。
- 不通过 `display: none` 和重新插入 DOM 来制造动画，避免点击目标和手势区域瞬间变化。
- 浮层层级必须显式定义，避免后续继续叠加 z-index。
- 支持 `prefers-reduced-motion`，减少动画敏感用户的不适。
- 每类优化独立提交，便于回滚和定位回归。

## 浮层视觉层级

### 目标

让沉浸式制作界面从“多个按钮盖在图纸上”变成“专业编辑器的轻量覆盖层”。用户的视觉焦点仍是图纸，工具只在需要时形成清晰层级。

### 层级定义

建议建立清晰的视觉层级，而不是继续为每个控件单独写 z-index：

| 层级 | 内容 | 视觉策略 | 交互要求 |
| --- | --- | --- | --- |
| L0 | 图纸画布、格子、色号 | 保持当前渲染 | 当前手势模型不变 |
| L1 | 被动状态提示、切板提示 | 轻量半透明边缘胶囊 | 不抢占手势 |
| L2 | 缩放条、复位入口、工具入口 | 玻璃质感浮层、弱阴影 | 点击区域不变 |
| L3 | 工具抽屉、设置面板、总览面板 | 明确面板层、背景弱压暗 | 打开时冻结底层画布 |
| L4 | 弹窗、导出、确认类操作 | 最高层模态 | 按现有模态规则 |

### 视觉处理

- 浮层统一使用柔和边框、轻量阴影和半透明背景，避免实心大块遮挡图纸。
- 高频入口保持可识别，但视觉权重低于图纸和当前格子。
- 面板层可以使用轻微背景模糊或弱遮罩，但不能让图纸完全不可见。
- 所有视觉变化只改样式，不改变浮层是否存在、是否可点击、是否冻结底层。

### 风险判断

| 风险项 | 是否影响 |
| --- | --- |
| 手势优先级 | 否 |
| 切板模型 | 否 |
| 冻结模型 | 否 |
| 拖动边界 | 否 |
| 图纸布局 | 否 |
| 是否需要独立开关 | 否，样式局部隔离即可 |
| 是否需要 A/B 验证 | 否，MCP 加真机对比足够 |
| 是否建议单独提交 | 是 |

## 状态提示视觉

### 目标

让状态提示更像编辑器反馈，而不是遮挡图纸的提示块。提示必须能让用户理解当前状态，但不能覆盖正在制作的核心区域。

### 设计约束

- 所有状态提示只能贴近顶边、底边或侧边。
- 不允许把“已切换板”“缩放 120%”“区域信息”等提示长期放在图纸中心。
- 提示文案保持短句，优先显示关键状态，不扩展成长说明。
- 状态提示不参与 layout，不推动图纸或工具位置。
- 只调整视觉样式和边缘化位置，不改变触发条件和业务状态。

### 建议样式

- 使用小型胶囊形态。
- 背景透明度高于普通工具层，但低于模态面板。
- 当前操作强相关提示使用轻微强调色。
- 次要提示降低透明度，避免持续抢视觉焦点。
- 超短反馈可使用 120ms-180ms 淡入，退出时不影响点击。

### 风险判断

| 风险项 | 是否影响 |
| --- | --- |
| 手势优先级 | 否 |
| 切板模型 | 否 |
| 冻结模型 | 否 |
| 拖动边界 | 否 |
| 图纸布局 | 否 |
| 是否需要独立开关 | 否 |
| 是否需要 A/B 验证 | 否 |
| 是否建议单独提交 | 是 |

## 基础动画过渡

### 目标

补齐沉浸式界面的基础顺滑感，让浮层出现、弱隐藏、展开和关闭更自然，但不改变任何手势和点击逻辑。

### 动画范围

- 工具抽屉打开和关闭：只做 `opacity` + `translate` + 轻微 `scale`。
- 状态提示出现和消失：只从边缘轻微滑入或淡入。
- 浮层弱隐藏和恢复：只做透明度变化，不改变占位，不改变点击区域。
- 总览层出现和关闭：只做轻量淡入，不改变当前位置和尺寸逻辑。

### 动画参数

- 常规浮层进入：120ms-160ms。
- 面板展开关闭：160ms-220ms。
- 状态提示反馈：120ms-180ms。
- easing 使用 `cubic-bezier(0.2, 0.8, 0.2, 1)` 或项目中已有等价曲线。
- `prefers-reduced-motion: reduce` 下关闭位移动画，仅保留极短透明度变化或无动画。

### 禁止事项

- 不允许动画过程中临时扩大或缩小点击区域。
- 不允许动画过程中打开底层画布手势。
- 不允许通过动画改变画布容器高度。
- 不允许用 JS 定时器重排图纸。
- 不允许把手势结束、切板判断、复位逻辑绑定到动画完成事件。

### 风险判断

| 风险项 | 是否影响 |
| --- | --- |
| 手势优先级 | 否 |
| 切板模型 | 否 |
| 冻结模型 | 否 |
| 拖动边界 | 否 |
| 图纸布局 | 否 |
| 是否需要独立开关 | 否，先局部 CSS 隔离 |
| 是否需要 A/B 验证 | 暂不需要，真机对比验证 |
| 是否建议单独提交 | 是 |

## 开发边界

后续进入开发计划时，第一轮实现必须遵守以下边界：

- 不修改单板手势阈值。
- 不修改切板判断条件。
- 不修改 `clamp` 边界计算策略。
- 不修改工具抽屉冻结条件。
- 不修改画布容器高度、定位和安全区计算。
- 不新增长期本地存储。
- 不新增影响主操作流的新控件。
- 优先通过样式类、CSS 变量或轻量视觉 helper 完成。
- 如必须调整组件结构，只允许为了减少样式重复，不允许改变 DOM 在文档流中的占位关系。

## 提交拆分

建议拆成三个独立提交：

- `style: refine mobile immersive overlay hierarchy`
- `style: refine mobile immersive status hints`
- `style: add mobile immersive base transitions`

如果出现回归，按提交粒度回滚，不把三类视觉变化混在一个提交里。

## 验证方案

### 本地命令

- `cmd /c node --test TEST\single_board_interaction.test.mjs`
- `cmd /c npm.cmd run build`

### MCP 验证

- 手机视口 `390x844` 进入单板制作模式。
- 确认标题栏以下图纸区域仍铺满到底部。
- 确认缩放条、工具入口、状态提示、总览入口均不占 layout 高度。
- 100%、150%、200% 验证上下轻微平移仍存在且受限。
- 300% 以上验证图纸仍可上下左右自由拖动。
- 打开工具抽屉后验证底层画布拖动、缩放、点击、切板全部冻结。
- 多板图纸验证低倍率边缘拖动不会因为状态提示或浮层动画误切板。
- 复位后验证图纸回到合理居中状态。
- 动画过程中连续点击工具、复位、总览，不应出现点击丢失或底层误触。
- 检查控制台无新增错误。

### 真机验收

- 安卓和 iPhone 各验证一次缩放、拖动、切板、工具抽屉冻结。
- 观察浮层是否更清晰，但不能长期挡住当前制作区域。
- 观察状态提示是否边缘化，不能遮挡格子中心。
- 快速连续操作时，动画不能导致图纸跳动、按钮误触或手势延迟。

## 验收标准

- 图纸仍是第一视觉优先级。
- Phase1 的布局、手势、冻结、切板、拖动边界全部保持稳定。
- 浮层看起来更统一、更轻、更像专业移动端编辑器。
- 状态提示不再抢占图纸中心。
- 基础动画提升顺滑感，但不影响事件响应。
- 每项优化都可以独立回滚。
