# Adaptive Grid Design

## Goal

Improve making-mode grid readability without switching to global pure black lines. The first version keeps the default lightweight grid unchanged and adds an optional grid enhancement mode that uses region-level adaptive contrast, double-layer semi-transparent lines, and light emphasis around the current working area.

The feature must not reduce the visual priority of color IDs, the selected cell, selected-color spotlight highlights, current-board boundary, board completion state, color replacement, auto-jump-to-next-board, or paginated export.

## Scope

- Default mode remains visually unchanged.
- Enhanced grid mode applies only when the user enables it.
- Adaptive contrast is calculated by region, not by individual bead cell.
- The first version enhances the current board and viewport-center area only.
- Enhancement around selected-color clusters is deferred because it can compete with the existing spotlight/highlight system.
- The screen making canvas is the primary target.
- Export rendering may reuse the same style rules later, but the first implementation should treat export behavior as unchanged unless explicitly approved.

## 1. Default Mode vs Enhanced Mode

Default mode keeps the current lightweight grid:

- Small cell grid remains low-opacity and unobtrusive.
- 5x5 dashed cross guides remain subtle.
- 10x10 / physical-board partition lines remain stronger than the 5x5 helpers.
- Current board, selected block, selected cell, and color spotlight remain visually dominant.

Enhanced mode changes only the helper-grid rendering:

- Uses region-level brightness to choose a slightly light-biased or dark-biased grid treatment.
- Draws helper lines with two semi-transparent layers instead of pure black or pure white.
- Lightly strengthens the current board and the viewport-center working area.
- Keeps opacity and line width capped so the artwork does not look dirty.

Enhanced mode should be presented as a making assistance option, not as the default rendering style.

## 2. Grid Visual Hierarchy

The rendering order and visual hierarchy must remain stable:

1. Color ID text layer: highest priority, remains on the independent text overlay.
2. Selected cell and selected-color spotlight: above all grid helpers.
3. Current board boundary / current block boundary: stronger than all adaptive helper lines.
4. Physical-board boundary lines: strong, solid, and stable.
5. 10x10 physical partition lines: stronger than 5x5 dashed helpers.
6. 5x5 dashed cross helpers: readable in enhanced mode, but visibly secondary.
7. Small cell grid: lowest priority.

Recommended relative styling:

- Small cell grid: very thin, low alpha, no pure black or pure white.
- 5x5 dashed helper: double-layer dashed line, lower alpha than 10x10 partition lines.
- 10x10 partition line: double-layer or adaptive-tinted line, stronger than 5x5 but still below board boundaries.
- Current board boundary: keep existing stronger cyan/pink/board-focus styling.

## 3. Region-Level Adaptive Brightness and Cache

Do not calculate line color per individual bead. Per-cell switching would create noisy line fragments, visual flicker during pan/zoom, and unnecessary mobile canvas cost.

Use region-level brightness:

- Primary region: physical 10x10 blocks generated by existing board geometry.
- Working-area region: current board and viewport-center window.
- Optional fallback region: visible viewport average when board geometry is unavailable.

Brightness should be bucketed, not continuous:

- `lightRegion`: use a slightly darker top line with a very soft light underlay.
- `darkRegion`: use a slightly lighter underlay/top mix, still avoiding pure white.
- `mixedRegion`: use neutral double-layer styling.

Cache strategy:

- Cache brightness by `beadData` identity/version, board size, and region key.
- Reuse cached values during pan and pinch zoom.
- Recompute only when bead data, board size, or visible region set changes materially.
- Cap computation to visible regions plus a small buffer around the viewport.
- Never scan the full artwork on every animation frame.

## 4. drawCellSize Thresholds and Hysteresis

Grid visibility should depend on `drawCellSize`, but thresholds need hysteresis so helpers do not blink while the user pinches near a boundary.

Proposed first-version thresholds:

- Small cell grid:
  - show when `drawCellSize >= 7`
  - hide when `drawCellSize < 6`
- 5x5 dashed cross helper:
  - show when `drawCellSize >= 10`
  - hide when `drawCellSize < 8.5`
- Enhanced adaptive treatment:
  - activate when enhanced mode is enabled and `drawCellSize >= 9`
  - deactivate when `drawCellSize < 7.5`
- Current working area boost:
  - activate when enhanced mode is enabled and `drawCellSize >= 8`
  - deactivate when `drawCellSize < 6.5`

Line width must have an upper bound at high zoom. The grid should become easier to see, not continuously thicker.

## 5. Current Board and Viewport-Center Enhancement

The first version should enhance two stable working areas:

- Current board: strongest candidate because the user already understands board focus.
- Viewport center: useful in traditional mode or when the user pans a large image.

Recommended behavior:

- Current board receives a modest opacity boost for 5x5 and 10x10 helper lines.
- Viewport-center area receives a smaller boost than the current board.
- Areas outside these working regions stay in the lightweight style.
- The boost should be gradual by region, not a hard per-cell checkerboard.

Selected-color-nearby enhancement is deferred:

- It risks competing with selected-color spotlight.
- It can make highlighted color regions look over-outlined.
- It should be considered only after current-board and viewport-center enhancement passes real-device testing.

## 6. Performance Risks and Anti-Jank Boundaries

Main risks:

- Scanning all beads during every overlay redraw.
- Splitting every grid line into many cell-level segments.
- Frequent `strokeStyle` changes inside tight loops.
- Recomputing adaptive buckets during each pinch-zoom frame.
- Drawing too many double-layer lines at low zoom.

Boundaries:

- Adaptive calculations operate on visible 10x10 regions plus buffer only.
- Per-frame redraw may draw cached regions, but must not rescan full bead data.
- Do not use per-cell adaptive line color.
- Disable enhanced helpers below threshold.
- Keep line widths and alpha capped.
- Preserve current overlay architecture: base image canvas, helper overlay canvas, and text overlay canvas remain separate.

Expected performance profile:

- Default mode: unchanged.
- Enhanced mode at low zoom: near default cost because enhanced helpers are hidden or minimal.
- Enhanced mode at medium/high zoom: extra cost is acceptable if region cache is used and visible regions are capped.

## 7. MCP Real-Device Visual Acceptance Matrix

Use MCP/devtools mobile emulation first, then real Android/iOS checks on the formal domain after approval and deployment.

Required viewports:

- Mobile portrait: 390 x 844, DPR 2 or 3.
- Mobile narrow: 360 x 780.
- Desktop sanity check: 1280 x 800.

Required zoom states:

- Fit / about 100%.
- Medium zoom / about 200%.
- High zoom / about 500%.
- Pinch around threshold boundaries for 5x5 helper visibility.

Required artwork regions:

- Mostly light region: white, skin tone, pale yellow.
- Mostly dark region: black, dark blue, dark red.
- Mixed high-frequency region: hair/accessory/detail-heavy area.
- Current board boundary crossing.
- Current selected cell and selected-color highlight active.

Acceptance criteria:

- Default mode screenshots match the current lightweight visual style.
- Enhanced mode makes 5x5 dashed helpers readable on both light and dark regions.
- 10x10 partition lines remain stronger than 5x5 helpers.
- Current board boundary remains stronger than adaptive helper lines.
- Color ID text remains readable.
- Selected cell remains visually obvious.
- Selected-color spotlight is not diluted or overpowered by the grid.
- Pinch zoom near thresholds does not visibly flicker.
- Fast pan does not show obvious frame drops or delayed grid repaint.
- Areas outside current board / viewport center remain less visually busy.

Suggested screenshots or recordings:

- default-fit, default-medium, default-high.
- enhanced-fit, enhanced-medium, enhanced-high.
- enhanced-dark-region-high.
- enhanced-light-region-high.
- enhanced-selected-color-active.
- threshold-pinch-recording.

## 8. Rollback Plan

Rollback should be simple and isolated:

- Hide or remove the enhanced-grid setting.
- Disable adaptive styling and fall back to current fixed grid colors.
- Remove adaptive brightness cache if it causes memory or redraw issues.
- Keep existing physical-board geometry helpers unchanged.
- Keep existing 5x5 cross guide geometry unchanged.
- Keep export rendering unchanged unless a later implementation explicitly changes it.

If implementation is already deployed, a quick rollback can be done by forcing enhanced mode off and preserving the current default grid path.

## First-Version Recommendation

Implement only after this proposal is approved:

- Add an optional enhanced grid mode.
- Keep default rendering unchanged.
- Use region-level adaptive brightness with cached 10x10 region buckets.
- Draw adaptive helper lines as double-layer semi-transparent strokes.
- Enhance current board and viewport-center area only.
- Defer selected-color-nearby grid enhancement.
- Verify with the MCP visual matrix before formal rollout.
