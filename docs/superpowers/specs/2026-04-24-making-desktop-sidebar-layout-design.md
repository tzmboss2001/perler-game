# 桌面端制作页侧边栏布局设计

日期：2026-04-24
范围：`/mobile/making` 的桌面/宽屏浏览器布局优化
状态：草案，待用户确认

## 1. 背景

当前制作页在桌面浏览器中仍沿用大量移动端堆叠式信息区。即使经过一轮压缩，单板模式顶部与底部仍然会占用较多垂直空间，导致中间图纸区可视高度不够理想。

用户目标很明确：

- 在电脑浏览器或宽屏浏览器上，把非核心按钮移到屏幕一侧
- 尽可能把屏幕高度还给图纸
- 侧边栏支持折叠，而不是永久常驻

## 2. 设计目标

1. 桌面端图纸区高度优先，减少顶部与底部占高。
2. 手机端与窄屏布局保持不变。
3. 桌面端工具区改为可折叠侧边栏，默认展开。
4. 用户收起后保留明显但不打扰的重新展开入口。
5. 折叠状态和展开状态写入本地，保留用户习惯。

## 3. 适用范围

仅在以下条件启用新布局：

- `viewMode === "singleBoard"` 或 `viewMode === "traditional"`
- 浏览器宽度大于桌面阈值，建议先用 `viewportWidth >= 1280`

以下场景不启用：

- 手机端
- 小平板和中等宽度窗口
- 窄屏浏览器

## 4. 方案对比

### 方案 A：顶部继续压缩

继续在现有顶部和底部做微调，不新增侧边栏。

优点：

- 改动最小
- 风险最低

缺点：

- 收益已经接近上限
- 单板模式仍会继续和图纸区抢高度
- 不能根本解决桌面端“工作台感”不足的问题

### 方案 B：桌面端可折叠侧边栏工作台（推荐）

中间图纸区单独成主列，工具和辅助信息迁移到侧边栏。

优点：

- 能明显释放垂直空间
- 同时保留桌面端更完整的工具能力
- 可折叠，兼顾新手和熟练用户

缺点：

- 布局改动中等
- 需要处理折叠状态与响应式阈值

### 方案 C：完整桌面独立页壳

桌面端做成与移动端几乎完全分离的工作台。

优点：

- 长期最强
- 桌面体验最好

缺点：

- 改动范围过大
- 回归风险最高
- 当前任务不需要一下走这么远

## 5. 推荐方案

采用方案 B：

- 桌面宽屏下使用“中间主图纸 + 右侧可折叠侧边栏”
- 默认展开
- 用户可手动收起
- 本地记忆折叠状态

这样既能明显释放图纸高度，也不会把当前制作页彻底重做成两套系统。

## 6. 桌面端新布局

### 6.1 总体结构

桌面宽屏下改为三段视觉层级：

1. 顶部薄工具条
2. 主工作区
3. 底部极简状态条

其中主工作区内部为：

- 左侧或中间主图纸区
- 右侧可折叠侧边栏

本次推荐把侧边栏放在右侧，原因：

- 当前阅读方向自然
- 不遮挡左上返回与模式切换心智
- 和“设置/总览/辅助工具”更匹配

### 6.2 顶部薄工具条保留项

顶部只保留最核心且需要一直可见的内容：

- 返回按钮
- 模式切换
- 当前板核心状态摘要
- 缩放条
- 主操作按钮：完成当前板

以下内容不再占顶部主高度：

- 总览卡片
- 设置
- 图纸导出
- 辅助开关
- 详细进度说明
- 大块未完成列表

### 6.3 主图纸区

主图纸区成为桌面端第一优先区域：

- 尽量占满可用高度
- 不再被总览和辅助面板上下挤压
- 图纸 canvas 外层只保留必要留白

预期结果：

- 图纸区域在桌面端明显高于当前版本
- 单板模式和传统模式都统一获得更大的中间制作区

### 6.4 右侧可折叠侧边栏

侧边栏默认展开，收纳以下模块：

1. 总览卡片
2. 板块切换
3. 当前板详细信息
4. 图纸导出
5. 设置 / 辅助能力

收起后：

- 侧边栏缩成一条窄边
- 保留一个明显的展开按钮
- 不完全消失，避免可发现性差

### 6.5 底部状态条

底部保留，但缩成极简一行：

- 当前坐标
- 当前板任务摘要
- 上一板 / 下一板 / 复位等次级动作

底部状态条只承担“快速查看 + 少量次级按钮”，不再承担主要工具区角色。

## 7. 单板模式内容迁移

单板模式中，以下内容迁移进右侧侧边栏：

- 整图总览
- 板块 chip 列表
- 未完成板列表
- 自动切下一板开关
- 当前板详细进度

顶部仅保留：

- 单板模式标签
- 当前板编号摘要
- 完成按钮
- 缩放

这样单板模式不会再因为“工作流说明 + 总览 + 板切换”持续挤压图纸高度。

## 8. 传统模式内容迁移

传统模式问题比单板模式轻，但桌面端也能受益于同样结构。

传统模式侧边栏承接：

- 设置
- 换色入口
- 图纸导出
- 辅助功能
- 选区说明

传统模式中间图纸区同样优先吃高度。

## 9. 折叠策略

### 默认行为

- 首次进入桌面宽屏：侧边栏默认展开

### 用户交互

- 点击侧边栏顶部的折叠按钮即可收起
- 收起后右边保留窄边按钮条
- 点击窄边按钮条可重新展开

### 状态持久化

本地存储字段建议新增：

- `makingDesktopSidebarCollapsed`

行为：

- 仅记录桌面端宽屏的侧边栏状态
- 不影响手机端

## 10. 阈值建议

建议按两个条件决定是否启用桌面侧边栏布局：

1. `viewportWidth >= 1280`
2. 指针环境为桌面细指针优先，避免平板误命中桌面布局

这样可以减少中等宽度窗口下“侧边栏吃掉横向空间”的副作用。

## 11. 风险与控制

### 风险 1：中等宽度窗口横向空间不够

控制方式：

- 只在更宽阈值下启用
- 侧边栏宽度做上下限

### 风险 2：用户找不到折叠后的入口

控制方式：

- 折叠后保留窄侧边可见入口
- 图标与文案明确，例如“展开工具”

### 风险 3：把现有制作操作打乱

控制方式：

- 只迁移非核心按钮
- 核心制作交互仍留在图纸附近

## 12. 验收标准

### 布局

- 桌面宽屏下，中间图纸区高度明显增加
- 单板模式不再因为顶部信息区而显著压缩图纸区
- 传统模式不退化

### 交互

- 侧边栏可展开 / 可折叠
- 折叠状态可记忆
- 展开入口可发现

### 回归

- 手机端布局不变
- 单板模式与传统模式都可正常切换
- 总览、设置、图纸导出、辅助功能在桌面端都能正常使用

## 13. 实施顺序

1. 抽出桌面宽屏布局开关 helper
2. 做桌面端右侧侧边栏壳子
3. 把总览 / 设置 / 图纸 / 辅助迁入侧边栏
4. 压缩顶部与底部主区
5. 加入折叠状态持久化
6. 做 MCP 桌面与手机双回归
