# 桌面端单板制作模式布局压缩优化设计

日期：2026-04-23

## 背景

当前制作页在桌面浏览器中仍然沿用移动端页面壳子和堆叠式信息结构。单板模式下，顶部和底部同时堆了较多模块：

- 模式切换
- 继续上次制作
- 单板进度状态
- 工作流操作
- 总览卡片
- 缩放工具带
- 底部任务条

在桌面端视口高度有限时，这些模块会明显挤压中间画布区，导致“屏幕很宽，但工作区很矮”的问题。手机端目前没有同样的异常，因为其交互本来就是围绕紧凑垂直布局设计的。

## 目标

- 仅优化桌面端单板模式的布局密度
- 明显提升中间制作区的可视高度
- 不破坏手机端现有交互
- 不重做整页架构，只做可控的桌面压缩优化

## 不做的内容

- 不改 `/mobile` 路由体系
- 不重做为完整左右三栏桌面工作台
- 不修改手机端布局
- 不改变单板模式核心交互逻辑

## 方案对比

### 方案 A：仅压缩间距与字号

- 把顶部卡片、按钮、边距整体缩小
- 保持现有信息区顺序和分块方式

优点：

- 改动最小
- 风险低

缺点：

- 只能回收少量高度
- 根因仍是“模块纵向堆叠过多”

### 方案 B：桌面端横向工具带压缩布局

- 桌面端单板模式把顶部多个模块收敛成更紧凑的两层
- 总览、工作流操作、缩放工具带横向重排
- 画布区优先占高度
- 底部任务条缩薄

优点：

- 能明显回收制作区高度
- 不需要推翻现有页面结构
- 风险和收益比较平衡

缺点：

- 需要补桌面端专用布局分支

### 方案 C：完整桌面工作台重构

- 左工具栏 + 中画布 + 右总览侧栏

优点：

- 桌面体验最好

缺点：

- 改动过大
- 更容易引入回归
- 不适合当前快速优化目标

## 选型

采用方案 B。

原因：

- 当前问题本质是桌面端仍在使用移动端堆叠结构
- 方案 B 能直接解决“画布区被顶部和底部挤压”的根因
- 同时改动范围仍然可控，适合当前阶段

## 设计方案

### 1. 增加桌面端单板模式专用布局分支

新增桌面判断：

- `viewMode === "singleBoard"`
- `viewportWidth > 640`

在这个分支下，单板模式的头部区域不再完全沿用现有纵向堆叠方式，而是切换到桌面压缩布局。

### 2. 顶部区压缩为两层

#### 第一层：模式与状态

保留：

- 传统模式 / 单板模式切换
- 当前板状态
- 继续上次制作
- 自动切换开关

调整为更紧凑的一行或两段横向区块，减少垂直占高。

#### 第二层：工具带

把这些内容并到一条横向工具带：

- 总览展开/收起
- 缩放控制
- 适板
- 完成当前板
- 图纸
- 辅助

目标是让桌面端工具区像工作台工具条，而不是一块块卡片往下排。

### 3. 总览区横向嵌入，不再单独吃大块高度

桌面端当前的总览信息区会单独占一块高度。优化后改成：

- 收起时只保留一行入口
- 展开时总览卡片嵌入工具带右侧或上方紧凑区域
- 默认更小，减少垂直占高

总览功能不删，但优先保证画布区高度。

### 4. 当前板工作流区收薄

当前“当前板工作流”区块在桌面端占高较多。优化后：

- 标题弱化
- 操作按钮压缩
- 信息改为紧凑行内展示

原则是保留信息，但不再让它看起来像独立大卡片。

### 5. 底部任务条压缩

底部：

- `板号 / 行列 / 任务进度 / 剩余 / 完成 / 上一板 / 复位 / 下一板`

保留，但整体高度收窄，按钮缩薄，减少对画布底部的侵占。

### 6. 画布区优先级上升

目标结果是：

- 桌面端单板模式下，优先把可用高度还给 `canvasContainer`
- 当前大宽屏场景下，画布区高度应明显高于当前版本
- 视觉重点重新回到制作区，而不是外围 UI

## 实现边界

### 修改文件

主要集中在：

- `perler-beads/src/pages/mobile/MakingPage.tsx`

如样式逻辑过于拥挤，可考虑补一个桌面单板布局 helper 或局部 style helper，但不做无关拆分。

### 状态复用

已有状态尽量复用：

- `singleBoardOverviewCollapsed`
- `resumeBoardNumber`
- `autoAdvanceOnBoardDone`
- `activeBoardNumber`
- `singleBoardProgress`

不新增无必要状态。

## 风险与控制

### 风险 1：桌面和手机端样式串扰

处理：

- 所有压缩布局都挂在桌面单板条件分支下
- 不修改手机端条件分支结构

### 风险 2：总览交互被压坏

处理：

- 只调整桌面总览摆放位置和默认尺寸
- 不改总览点击跳板逻辑

### 风险 3：底部任务条可读性下降

处理：

- 只压缩高度，不隐藏核心信息
- 优先压边距、按钮高度和区块留白

## 验收标准

- 桌面端单板模式下，中间制作区高度明显增加
- 顶部信息区不再一层层明显堆叠压缩画布
- 总览、缩放、完成、图纸、辅助仍可直接操作
- 底部任务条仍可读、可操作
- 手机端单板模式表现不变

## 验证计划

- 本地构建：
  - `npm.cmd run build`
- MCP 桌面端验证：
  - 1680 宽度下打开单板模式
  - 对比调整前后制作区高度
  - 验证总览、缩放、翻板按钮、底部任务条
- MCP 手机端回归：
  - 确认手机端单板模式入口和总览不受影响
